# Artifact Strategy

Artifacts preserve the evidence and files produced by planning, workers, QA, bugs, and release preparation. They must be addressable from the API/Hub without forcing large files into the database.

## Storage Policy

Small text artifacts may be stored inline in `Artifact.content` when doing so improves inspection and tests. Current examples include:

- `mission.md`
- `acceptance.md`
- `technical-notes.md`
- `risk-notes.md`
- `codex-prompt.md`
- `codex-command.sh` review artifact
- `dev-summary.md`

Large or binary artifacts must be stored path-only with metadata, not inline content. Examples:

- screenshots;
- Playwright traces;
- HTML reports;
- long logs;
- archives;
- generated videos;
- large JSON reports.

For path-only artifacts, keep these fields accurate:

- `path`
- `type`
- `size`
- `mime_type`
- `metadata`
- optional `worker_run_id`

## Path Boundaries

Local generated artifacts belong under repository-managed roots:

```text
missions/<mission-id>/
artifacts/missions/<mission-id>/
```

Worker project clones belong under:

```text
workspaces/<project-id>/
```

Do not store artifacts outside the repository-managed roots unless a later object-storage policy explicitly documents the location and access controls.

Artifact paths should be stable, relative, and free of secrets. Avoid spaces in generated paths.

## Content Boundaries

Artifact content must not include:

- API tokens;
- provider keys;
- cookies;
- database passwords;
- private deployment credentials;
- raw `.env` content;
- unredacted logs containing sensitive values.

Prompts, logs, PR bodies, QA reports, and comments must use redacted values when environment or credential-like strings are relevant.

## Database Boundary

The database may store inline content for small markdown/text review artifacts. It should not be used as a blob store. When a file is large, frequently rewritten, binary, or generated by QA tooling, store the path and metadata in the database and keep the file in the artifact root.

Current API behavior accepts `content` for `POST /missions/:missionId/artifacts`, but callers are responsible for applying this size and sensitivity policy.

## Current Batch

The current dry-run batch stores planner and Codex review artifacts as small text records and local mission files. QA screenshots, traces, Playwright reports, and large logs are not implemented yet and should be path-only when added.
