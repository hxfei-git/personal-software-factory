# Codex Worker Dry Run

The Codex Worker currently implements only a deterministic dry-run generator. It prepares the artifacts that a later real worker will need, while preserving the safety boundary required before any live Codex execution exists.

## Inputs

`createCodexDryRun` accepts:

- `missionId`;
- `projectId`;
- `branchName`;
- `currentBranch`;
- Project Passport;
- project `AGENTS.md` content;
- Mission files: `mission.md`, `acceptance.md`, `technical-notes.md`, and `risk-notes.md`;
- `mode`, defaulting to `dry-run`.

## Outputs

The generator returns in-memory records and file contents only:

- `codex-prompt.md`;
- `codex-command.sh`;
- `dev-summary.md`;
- `WorkerRun` with `worker_type: "codex"` and `mode: "dry-run"`;
- `Artifact[]` with `codex_prompt`, `codex_command`, and `dev_summary` types;
- `MissionEvent[]` including `worker_run.created` and `codex.dry_run.created`;
- `executed: false`.

The generated command is an artifact, not an action:

```bash
codex exec --sandbox workspace-write --ask-for-approval on-request "<mission prompt>"
```

## Prompt Contract

The prompt instructs Codex to:

1. Read `mission.md`.
2. Read `acceptance.md`.
3. Read `technical-notes.md`.
4. Read `risk-notes.md`.
5. Read project `AGENTS.md`.
6. Not modify `main` or `master`.
7. Create an independent branch.
8. Implement the requirement.
9. Run project-required tests from the Project Passport.
10. Generate `dev-summary.md`.
11. Not directly publish production.
12. Not push remote unless explicitly authorized.

## Safety Boundary

Dry-run mode never calls Codex. It also never clones repositories, creates worktrees, modifies `workspaces/`, pushes remotes, or calls external services.

The shared guard `assertSafeCodexExecution` blocks real mode unless the caller provides all required approval signals:

- `enableRealCodex: true`, representing `ENABLE_REAL_CODEX=1`;
- `hasApproval: true`, representing an approved Approval record;
- `currentBranch` is not `main` or `master`.

`danger-full-access` is not generated by the dry-run command. The command uses `workspace-write` and `on-request` approval mode.

## Current Non-Goals

This package does not yet implement the Phase 7 real worker capabilities from the roadmap: repository clone/update, branch/worktree creation, Mission file injection, command execution, test execution, local commits, or PR creation. Those behaviors require separate approval, mock-first testing, and state-machine integration in later tasks.
