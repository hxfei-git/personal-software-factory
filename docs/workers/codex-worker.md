# Codex Worker Dry Run

The Codex Worker keeps the deterministic dry-run generator as the default path and now also exposes a gated runner abstraction for later real execution. Real mode remains disabled by default, requires explicit approvals and environment gates, and must not call external provider APIs or push remotes.

## Inputs

`createCodexDryRun` accepts:

- `missionId`
- `projectId`
- required `branchName`
- `currentBranch`
- normalized Project Passport
- project `AGENTS.md` content
- Mission files: `mission.md`, `acceptance.md`, `technical-notes.md`, and `risk-notes.md`
- optional `mode`, defaulting to `dry-run`
- optional real-execution guard inputs used only by the safety check

## Outputs

The generator returns in-memory records and file contents:

- `codex-prompt.md`
- `codex-command.sh`
- `dev-summary.md`
- one `WorkerRun` with `worker_type: codex`, `mode: dry-run`, `status: succeeded`, and `executed: false` metadata
- `Artifact[]` with `codex_prompt`, `codex_command`, and `dev_summary` types
- `MissionEvent[]` including `worker_run.created` and `codex.dry_run.created`
- `executed: false`

The CLI writes these files under `missions/<mission-id>/` and syncs records to Prisma unless `PSF_SKIP_DB=1`.

## Prompt Contract

The generated prompt instructs a future Codex run to:

1. Read `mission.md`.
2. Read `acceptance.md`.
3. Read `technical-notes.md`.
4. Read `risk-notes.md`.
5. Read project `AGENTS.md`.
6. Avoid modifying `main` or `master`.
7. Create an independent branch.
8. Implement the requirement.
9. Run project-required tests from the Project Passport.
10. Generate `dev-summary.md`.
11. Avoid direct production publishing.
12. Avoid remote push unless explicitly authorized.

## Command Artifact

The package-level command string is review material for a future executor:

```bash
codex exec --sandbox workspace-write --ask-for-approval on-request '<mission prompt>'
```

The CLI intentionally writes `codex-command.sh` as a non-executable safety artifact:

- file mode is `0644`;
- the reviewed `codex exec` command is stored as comments only;
- running the file exits with status `1`;
- running the file does not invoke Codex.

## Safety Boundary

Dry-run mode never:

- calls `codex exec`;
- clones repositories;
- creates worktrees;
- modifies `workspaces/`;
- runs project install/build/test commands;
- commits code;
- pushes remotes;
- creates PRs;
- calls external services.

`ENABLE_REAL_CODEX=1` is a required real-runner gate. With the default `ENABLE_REAL_CODEX=0`, `mode: real` returns a blocked result before spawning any process.

The shared guard `assertSafeCodexExecution` blocks `mode: real` unless all conditions are true:

- `enableRealCodex` is true, representing `ENABLE_REAL_CODEX=1`;
- `hasApproval` is true, representing an approved Approval record;
- `currentBranch` is not `main` or `master`.

`danger-full-access` is not generated by dry-run. The reviewed command uses `workspace-write` and `on-request` approval mode.

## Runner Abstraction

The package exports a `CodexRunner` interface with three implementations:

- `DryRunCodexRunner` returns a non-executing dry-run style result.
- `MockCodexRunner` returns a deterministic mock result without spawning Codex.
- `RealCodexRunner` validates all gates before spawning the executable configured by `CODEX_EXECUTABLE`. Tests use local mock executables only; the runner does not look up `codex` from `PATH`.

Real runner request validation is handled by `CodexExecutionRequestSchema`. Required request fields are `missionId`, `projectId`, `repoUrl`, `defaultBranch`, `missionFiles`, `approvalIds`, `commands`, `branchName`, `workspaceRoot`, `timeoutMs`, and `mode`.

## Workspace Leasing

`leaseCodexWorkspace` supports local repository fixtures and local mirrors only. It creates a git worktree under `PSF_WORKSPACE_ROOT` using a new `agent/<slug>-<mission-id>` style branch, refuses `main` and `master` as execution branches, rejects traversal attempts, and returns `manual_action` when the target branch or workspace path already exists or when a repository has no `origin` remote. It does not force-reset existing agent branches. Remote clone/update remains a manual operator preparation step for now.

## Real Runner Artifacts

When a gated real run executes an explicit executable, prompt, command, stdout, stderr, diff summary, and local commit summary are redacted with `@psf/security` before being returned or persisted. Secret-like environment variable values, such as token/password/secret/authorization/cookie/session/JWT/API-key values, are passed as extra redaction secrets so a mock or real executable cannot leak raw env values into results or artifacts. The runner uses `@psf/artifact-store` for prompt, command, stdout, stderr, dev summary, diff summary, and local commit summary artifacts. Push is disabled, and no external provider APIs are called.

## Real Runner Gates

Before workspace leasing, the runner blocks unsafe CLI policy and project commands. `CODEX_SANDBOX` is limited to `workspace-write` or `read-only`, and `CODEX_APPROVAL_MODE` is limited to `on-request`. Project commands are checked with the shared command policy before any worktree or agent branch is created, then checked again inside the leased workspace. Timed-out child processes receive `SIGTERM`, then `SIGKILL`, with a hard fallback so ignored termination does not hang the worker.

## Queued Worker Runner Boundary

Batch 03/04 Worker Runner `codex.real` jobs consume Orchestrator queued payloads only after preflight confirms a local `repoUrl` and an `agent/*` branch. The queued payload carries local mirror path, default branch, workspace root, Project Passport, Mission files, project `AGENTS.md`, safe commands, approval record IDs, and approval grant IDs.

Task 8 does not make Worker Runner spawn real Codex by default. Without an explicitly injected Codex runner, the handler returns `manual_action` and records a safe wrapper/action-result summary. Injected runners are used for fixture proof and tests; they are not evidence that a real `codex exec`, AI provider call, push, PR, deployment, or external network operation occurred.

## Current Non-Goals

This package still does not implement remote repository clone/update, arbitrary command execution from Hub/API, remote push, PR creation, production deployment, external provider calls, or default Worker Runner spawning of real Codex. Real mode is a gated local runner surface for approved operator-controlled execution only, and the Worker Runner integration remains injected-runner/manual-action until a later approved phase intentionally enables real execution.
